## Executive Summary

A comprehensive, ground-truth audit of all behavioral datasets, telemetry logs, scripts, and model serialization artifacts in the repository was executed. The audit identified crucial discrepancies between documented figures and actual disk contents, uncovered critical data leakage between validation and test partitions, discovered synthetic target leakage in sensor features, and diagnosed severe numerical anomalies in live mouse kinematics.

## 2. Detailed Audit Findings (Items 1 - 11)

### 1. Actual Counts, Session Counts, User Counts, and Durations
- **Session Files:** Exactly **6 session files** in `data/harvested/sessions/`.
- **Total Windows:** Exactly **180 windows** (30 windows per session $\times$ 5 seconds/window = 150 seconds / 2.5 minutes per session).
- **Total Recording Time:** 900 seconds (15 minutes total: 7.5 min owner, 7.5 min imposter).
- **Users:** Exactly **4 distinct user identities**:
  1. `Owner_Anush` (Authorized Owner): 3 sessions, 90 windows (450 seconds / 7.5 minutes) across tasks: `coding`, `docs`, `browsing`.
  2. `Attacker_Mimic` (Unauthorized Imposter): 1 session, 30 windows (150 seconds / 2.5 minutes), task: `imposter_mimic`.
  3. `Teammate_Akash` (Unauthorized Imposter): 1 session, 30 windows (150 seconds / 2.5 minutes), task: `coding`.
  4. `Teammate_Pratheek` (Unauthorized Imposter): 1 session, 30 windows (150 seconds / 2.5 minutes), task: `docs`.

### 2. Reconciliation of Dataset Count Inconsistencies
> [!IMPORTANT]
> **Resolution of the "90 Owner Sessions" Discrepancy:**
> Previous reports documented *"90 owner sessions, 72 training samples, 9 validation samples, 108 test samples, and 90 imposter samples"*.
> 
> **Reconciliation:**
> - There are **NOT 90 owner sessions**. There are only **3 owner sessions** of 30 five-second windows each. The term "sessions" was mistakenly used to describe individual 5-second **windows/samples**.
> - The 90 owner windows were partitioned via an 80/20 split:
>   - $90 \times 0.80 = 72$ training samples $\to$ `train_owner.jsonl`.
>   - The remaining 18 owner samples were assigned to test $\to$ `test_multimodal.jsonl`.
>   - The validation split (`val_owner.jsonl`) took $18 // 2 = 9$ samples directly from the 18 test owner samples.
>   - The multimodal test set combined the 18 test owner samples with all 90 imposter samples ($18 + 90 = 108$ samples).
> - **Conclusion:** The counts are now 100% accounted for, but reveal severe methodological flaws: validation is a complete subset of the test set, and window-level shuffling destroyed temporal session integrity.

### 3. Class Balance and Label Semantics
- At the overall harvested dataset level: 90 authorized vs. 90 unauthorized (50.0% balance).
- In `test_multimodal.jsonl`: 18 authorized vs. 90 unauthorized (16.7% authorized vs. 83.3% unauthorized). This severe test imbalance means Accuracy is misleading and PR-AUC / ROC-AUC / EER must be reported.

### 4. Missing, Corrupted, and Non-Finite Values
- In `data/harvested/`: 0 nulls, 0 non-finite values.
- In `telemetry_data.jsonl` (live Windows telemetry agent):
  - `mouse_jerk_mean` has extreme numerical overflow: minimum **$-313,803,077.07$**, maximum **$+97,134,556.17$**, mean **$-1,664,512.15$**.
  - **Root Cause:** In `telemetry/agent.py` line 557, jerk is calculated as `da / dt` where $dt = (times[i+3] - times[i+1]) / 2$. On high-polling-rate mice under Windows, timer resolution can produce $dt < 0.0005$ seconds. Without a minimum $dt$ threshold or derivative clamping, division by near-zero explodes derivatives into the millions.
  - Furthermore, 407 out of 1,675 windows (24.3%) have zero keystroke events (idle windows).

### 5. Feature Distributions & Synthetic Artifacts
In `data/harvested/sessions/*.jsonl`:
- `cpu_usage` is constant at exactly `3.8%` across all 180 rows.
- `ram_usage_mb` is constant at exactly `420.0 MB` across all 180 rows.
- `mouse_straightness_mean` is hardcoded to exactly `0.91` for all 90 authorized rows, and exactly `0.72` for all 90 unauthorized rows.
- Keystroke dwell and flight standard deviations are linearly generated from means ($std = mean \times 0.15$ and $mean \times 0.18$).

### 6. Session IDs, Timestamps, and Source Provenance
- All 6 session files share the identical base epoch timestamp: `1791303424`.
- They were created by a single synthetic batch run of `generate_simulated_session()` in `scripts/harvest_real_telemetry.py`.
- None of the 6 files were captured from live hardware keystrokes or mice.

### 7. Session Splitting and Cross-Split Contamination
- **Temporal Window Leakage:** In `DatasetPartitioner.partition_dataset()`, `random.shuffle(owner_records)` was invoked across all 90 owner windows before slicing.
- Consequently, 5-second windows from the same 2.5-minute coding session appear in BOTH `train_owner.jsonl` (e.g. window at $t=10s$) and `test_multimodal.jsonl` (e.g. window at $t=15s$). The model is evaluated on neighboring temporal slices of the exact same continuous typing sequence.

### 8. Training, Validation, and Test Overlap
- **100% Validation Overlap:** All 9 samples in `val_owner.jsonl` are identical byte-for-byte to samples present in `test_multimodal.jsonl`.
- Tuning thresholds or hyperparameters on `val_owner.jsonl` directly optimizes performance on the test set.

### 9. Synthetic and Real-World Data Mixing
- `data/harvested/` was represented as "Real Telemetry", but consists entirely of Gaussian-sampled synthetic data.
- `data/raw/*.csv` are synthetic mock data created by `tests/generate_mock_data.py`.
- Real user telemetry exists only in `telemetry_data.jsonl`, but lacks session and user ground-truth labels.

### 10. Direct Target Feature Leakage
> [!CAUTION]
> **Severe Target Leakage in Environmental Features:**
> - In `data/harvested/sessions/`, `ble_proximity_state` is set to `"IMMEDIATE"` for 100% of authorized samples and `"OUT_OF_RANGE"` for 100% of unauthorized samples.
> - `ble_estimated_distance_m` is hardcoded to `0.8m` for authorized and `9.5m` for unauthorized.
> - Because `telemetry/evaluator.py` applies a $+0.25$ penalty when BLE is `"OUT_OF_RANGE"`, any detector reading BLE proximity receives a trivial artificial shortcut that separates the classes with zero false alarms, entirely masking whether behavioral biometrics actually work.

### 11. Feature Schema Inconsistency (Training vs. Inference)
- **Missing Keystroke Sequences in Real-Time Agent:**
  - `telemetry/evaluator.py` lines 115-121 evaluate Deep SVDD 1D-CNN via `telemetry_row["dwell_sequence"]` and `telemetry_row["flight_sequence"]` (lists of 30 floats).
  - However, `telemetry/agent.py` line 608 (`_aggregate_and_output`) **never extracts or outputs `dwell_sequence` or `flight_sequence`**!
  - When live telemetry is fed from `agent.py` to `evaluator.py`, the sequence check fails, triggering a fallback in `evaluator.py` (lines 129-150) that fabricates random uniform sequences on the fly or samples from `data/raw/keystrokes.csv`.
- **Mouse Kinematics Divergence:**
  - In `harvest_real_telemetry.py`, acceleration and jerk use a hardcoded $\Delta t = 0.05s$.
  - In `telemetry/agent.py`, acceleration and jerk use variable $\Delta t = (t_{i+2} - t_i)/2$ without lower bounds.
  - In `ml_engine/models.py`, `mouse_acceleration_mean` and `mouse_jerk_mean` are preprocessed with $\text{sign}(x) \cdot \ln(1 + |x|)$ to suppress extreme magnitudes.

## 3. Statistical Reliability Assessment

The current dataset of 180 synthetic 5-second windows across 6 sessions (totaling 15 minutes of synthetic data) is **statistically insufficient** for evaluating continuous authentication in real-world deployment. Specifically:
1. It does not reflect genuine multi-day behavioral drift (circadian rhythm, fatigue, task variation).
2. It does not test device invariance (different mouse DPI, keyboard key switches).
3. It cannot measure cross-user generalization because only 3 imposter identities exist with 2.5 minutes of data each.

**Audit Recommendation:** Expand authorized behavioral coverage, fix the kinematics overflow and schema mismatch, implement strict session-level splitting, remove leaked target features, and benchmark genuine anomaly detection baselines.
